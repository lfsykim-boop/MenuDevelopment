# 설계 근거

이 스킬은 6개 설계 요소로 작동한다. SKILL.md의 각 절과 대응한다.

## 1 역할 Role
- 메뉴개발팀 = 개발의 주체·결정권자·실데이터 제공·최종 go/no-go
- 스킬 = 진행 구조화·트렌드/제철 리서치·5인 토론 운영·자료 공백 지적 (권고만)
- 스킬은 자사 수치를 지어내지 않는다

## 2 컨텍스트 Context
- 입력값과 실행 중 유지 항목(확정 콘셉트·트렌드 스냅샷·제철 매칭·자사 데이터·판정 이력·변경 영향 맵)
- 모든 수치에 [데이터] / [추정] / 자료 필요 태그
- 회사 기준 레퍼런스(references/company-reference.md)를 시작 시 읽음

## 3 도구 Tools
- WebSearch 트렌드·경쟁·가격대 (매 실행 재검색)
- 사용자 요청 자사 POS·가격 수용도·원가 실측 (검색으로 대체 금지)
- 내장 제철 참고표와 레퍼런스 제철 캘린더
- HTML 결과물 작성 (html-to-office 호환)

## 4 워크플로우 Workflow
- 레퍼런스 읽기 → 입력값 확정 → [단계 1~7: 트렌드·제철 → 산출물 → 5인 채점 → 판정 → 사용자 확인 → 변경 파급 재검토] → 최종 요약
- 사용자 체크포인트에서 스킬은 멈추고 사용자가 진행을 결정한다

## 5 평가 루브릭 Rubric
점수 구간 앵커로 자의적 채점을 막는다.

| 점수 | 근거 수준 |
|---|---|
| 10 | 자사 실데이터 + 리스크·대체안 완결 |
| 9.7~9.9 | 자사 실데이터 기반 경미한 보완 |
| 9.5~9.6 | 실데이터 있으나 표본·기간·단일 출처 한계 |
| 9.0~9.4 | 외부·타사 데이터로 방향만 |
| 7.1~8.9 | 핵심 근거가 추정 |
| 7.0 이하 | 근거 없음 또는 자료 필요 |

합격선 평균 9.7 개별 9.5. 단계당 최대 3회 재토론. 미달 시 중단·자료 요청.

## 6 가드레일 Guardrails
- G1 데이터 날조 금지
- G2 데이터 게이트 (자료 필요 → 9.5 상한, 추정 → 평균 9.7 미만, 근거 없음 → 7점 상한)
- G3 기준 하향 금지
- G4 사용자 최종권 (판정은 권고, 덮어쓰면 이유 기록)
- G5 트렌드 재검증 (브랜드 정합성·자사 수익으로)
- G6 제철 단종·대체 계획 없으면 원가 담당 9.5 상한

## 설계 의도
합격선과 가드레일은 **근거 없는 메뉴를 막는 장치**다. 데이터가 없으면 멈추고 사람에게 요청하는 것이, 환상 기획을 통과시켜 출시 실패로 가는 것보다 가맹점 수익을 지킨다.
